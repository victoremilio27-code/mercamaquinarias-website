# Fase 10.2 — Estrategia de validación

Sale de «Arquitectura de validación» de `10.2-RESEARCH.md`, ajustada a los planes 10.2-01 a 10.2-08 tras la
revisión del 2026-10-01 (B1-B4, W1-W9).

## Infraestructura

| Propiedad | Valor |
|-----------|-------|
| **Marco** | Arnés propio con contadores y `process.exit` (`tools/probar-telefono.js`; los textos y avisos en `tools/probar-contactos.js`), `tools/prueba-chat.js`, y puppeteer (`tools/auditar-*.js`) |
| **Configuración** | base desechable en `.tmp/prueba-telefono/`; `MERCA_DB`, `MERCA_CORREO=archivo`, `MERCA_SECRETO` fijados y `MERCA_SMS*`/`BREVO_API_KEY` borrados ANTES de `require('./db.js')`; el SMS se enciende a mitad de la ejecución con `MERCA_SMS=archivo` y se apaga en `finally` |
| **Reloj** | ninguna expectativa depende de la fecha: lo vencido se fuerza a `PASADO = 2000-01-01T00:00:00.000Z`, lo vigente a `FUTURO = 2999-01-01T00:00:00.000Z`; «hace un día» se calcula en SQL (`strftime(…, 'now', '-1 day')`); `ponerEnfriamiento` con `desde` inyectado; `enEnfriamiento` y `accionSmsReciente` son puras con `instante`; el tope diario es una ventana de 24 h de `db.permitir`. `grep -c "Date.now()" tools/probar-telefono.js` = 0 |
| **Asincronía** | las rutas públicas responden antes de buscar la cuenta (`setImmediate`): la prueba espera un tick antes de leer `.tmp/sms/` o la base |
| **Navegador** | SMS apagado: `auditar-flujos` y `auditar-permisos` contra el 8080 (como el CI). SMS encendido: `auditar-telefono` levanta su propio servidor en el 8091 con `MERCA_SMS=archivo` y base en `.tmp/auditar-telefono/` |
| **Comando rápido** | `npm run telefono:probar` |
| **Suite completa** | `npm run telefono:probar && npm run contactos:probar && npm run cuenta:probar && npm run seguridad:probar && npm run bitacora:probar && npm run dealer:probar && npm run renovacion:probar && npm run cardnet:probar && npm run chat:probar`; con el sitio de demostración en 8080, `npm run auditar` (incluye `auditar-telefono`) y `npm run check` |
| **Duración estimada** | ~10 s rápido; ~4 min completo |

## Muestreo

- **Tras cada tarea:** su comando de `<verify>` (casi siempre `npm run telefono:probar`; `contactos:probar` en el plan 02; `cuenta:probar` si se tocó `recuperar`, `restablecer` o `/cuenta/clave`).
- **Tras cada plan:** la suite completa del arnés.
- **Tras cada ola:** el orquestador (solo él, puerto 8080 fijo) mata servidores viejos con `lsof -t -i :8080 | xargs -r kill`, siembra con `npm run db:demo`, arranca el sitio y corre `npm run auditar` y `npm run check`. Tras la ola 4 comprueba además que no queda nada en el 8091.
- **Antes de verificar la fase:** todo lo anterior en verde.
