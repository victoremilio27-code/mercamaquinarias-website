<task type="auto">
  <name>Tarea 1: tabla y funciones de contactos en tools/db.js</name>
  <files>tools/db.js</files>
  <action>
  - Migración `['2026-09-contactos-verificados', [...]]` añadida como ÚLTIMA entrada de `MIGRACIONES`:
    tabla `contactos_verificados (id TEXT PK, organizacion_id TEXT NOT NULL REFERENCES organizaciones(id) ON DELETE CASCADE,
    numero TEXT NOT NULL, via TEXT CHECK (via IN ('correo','sms')), verificado TEXT, verificado_por TEXT,
    codigo_hash TEXT, codigo_via TEXT CHECK (codigo_via IN ('correo','sms')), codigo_expira TEXT,
    intentos INTEGER NOT NULL DEFAULT 0, creado TEXT NOT NULL, UNIQUE (organizacion_id, numero))`.
    `verificado_por` sin clave foránea: guarda quién lo confirmó aunque la persona deje la organización.
  - `normalizarNumero(n)`: solo dígitos; 11 empezando por 1 → quita el 1; devuelve 10 dígitos o `null`.
  - `pedirCodigoContacto({ idOrg, numero, via })` → `{ codigo, minutos }` o `{ yaVerificado: true }`.
    Upsert de la fila; HMAC con `SECRETO` sobre `contacto|org|numero|via|codigo`; 15 minutos; reinicia intentos.
  - `confirmarCodigoContacto({ idOrg, numero, codigo, idUsuario })` → `{ ok, via }` o `{ ok:false, motivo, restantes }`
    con motivos `inexistente`, `vencido`, `agotado`, `incorrecto`, `usado`. Comparación con `timingSafeEqual`;
    el consumo es un `UPDATE ... WHERE id = ? AND codigo_hash = ?` para que dos peticiones no pasen las dos.
  - `numerosVerificados(idOrg)` → `Map` numero → vía.
  - `contactosDe(idOrg)`: los números de la organización (verificados o pendientes) unidos a los que usan sus
    anuncios, con `verificado`, `via`, `fecha` y `anuncios` (cuántos anuncios lo llevan).
  - `marcarContactoVerificado(idOrg, numero, via, idUsuario)`: solo para la semilla y herramientas de consola;
    ninguna ruta de la API lo llama (lo vigila la prueba).
  - `anuncio()`: cada teléfono sale con `verificado` y `via`.
  - `purgar()`: borra filas nunca verificadas cuyo código venció hace más de un día.
  - Exportar todo.
  </action>
