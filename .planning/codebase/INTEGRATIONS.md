# External Integrations

**Analysis Date:** 2026-09-25

## Integration Philosophy

Every external service is called directly over HTTPS using Node's built-in `https` module — no vendor SDKs are installed (see STACK.md's zero-runtime-dependency policy). Each integration is isolated behind exactly one module: `tools/chat.js` is the only file that talks to Anthropic; `tools/correo.js` is the only file that talks to Brevo. New integrations should follow this pattern: one dedicated `tools/*.js` module wrapping a raw `https.request` call, not a new dependency.

## APIs & External Services

**AI / Support Assistant:**
- Anthropic Messages API — powers the floating support chat widget.
  - Client: hand-rolled HTTPS call in `tools/chat.js` (`https.request({ hostname: 'api.anthropic.com', path: '/v1/messages', method: 'POST' })`), no `@anthropic-ai/sdk`.
  - Auth: `ANTHROPIC_API_KEY` (env var name only — never logged or sent to the browser). Read via `CLAUDE()` closure in `tools/chat.js:26`.
  - Model: `MERCA_CHAT_MODELO` env var, default `claude-sonnet-5`. Cheaper alt `claude-haiku-4-5`, stronger alt `claude-opus-5` — configurable without a code change.
  - Extended thinking explicitly disabled (`PENSAR = { type: 'disabled' }`, effort `'low'`) since the assistant only answers from a pre-written FAQ prompt built from `assets/precios.js` and `assets/servicios.js`.
  - Request path: browser → `POST /api/chat` (handled in `tools/api.js`) → `tools/chat.js` → Anthropic. The key never reaches the browser.
  - Graceful degradation: if `ANTHROPIC_API_KEY` is unset, the chat still answers, just with an apology + support contact info instead of calling the API (documented in `.env.example` and `deploy/README.md`).
  - Rate limiting: `tools/api.js` LIMITES.chat caps at 30 messages / 15 minutes per requester, because each message is a paid API call.
  - Manual verification tool: `tools/prueba-chat.js` (`npm run chat:probar`) — stubs the request instead of spending real API credits.

**Transactional Email:**
- Brevo (formerly Sendinblue) SMTP & API — all outbound email (verification codes, quote requests, dealer approvals, invoices, expiry warnings, business reports).
  - Client: hand-rolled HTTPS call in `tools/correo.js` (`https.request({ hostname: 'api.brevo.com', path: '/v3/smtp/email', method: 'POST' })`), no Brevo/Sendinblue SDK.
  - Auth: `BREVO_API_KEY` (env var name only).
  - Transport selection: `MERCA_CORREO` env var — `archivo` (dev default: writes each message to `.tmp/correos/` instead of sending, prints the code to console) or `brevo` (production).
  - Sender: `MERCA_REMITENTE`, always a `no-reply@` address on a domain with SPF/DKIM/DMARC published in DNS (required or Gmail/Outlook spam-filter it) — see `deploy/README.md` step 9.
  - Free tier: 300 emails/day; overage surfaces as HTTP 402 from Brevo, logged by the service.
  - Manual verification tool: `tools/probar-correo.js` (`npm run correo:probar`).

## Data Storage

**Databases:**
- SQLite via Node's **built-in** `node:sqlite` module (`DatabaseSync`) — no `better-sqlite3`, no `sqlite3` npm package, no ORM/query builder. This is the reason Node ≥ 22.5 is a hard requirement.
  - Single access module: `tools/db.js` owns 100% of the SQL in the project; `tools/api.js` never writes raw SQL.
  - Connection: file path from `MERCA_DB` env var, defaulting to `db/mercamaquinarias.db` inside the repo (dev). In production it's moved outside the repo to `/var/lib/mercamaquinarias/mercamaquinarias.db` so `git pull` never touches it.
  - Schema: `db/schema.sql` (idempotent, `CREATE TABLE IF NOT EXISTS`), applied on every `abrir()`. Forward-only migrations for existing databases live as an ordered array in `tools/db.js` (`MIGRACIONES`, e.g. `2026-08-sucursales-contacto`, `2026-08-promociones`, `2026-08-revision-dealers`, `2026-08-avisos-vencimiento`, `2026-08-indices-catalogo`, `2026-08-taxonomia-jerarquica`) — never edit a past migration, only append.
  - Concurrency: `PRAGMA busy_timeout = 5000` set on open, so a write colliding with the nightly backup retries instead of surfacing `SQLITE_BUSY` as a 500.
  - Reset/seed tooling: `npm run db:reset` (deletes the db files), `npm run db:demo` / `db:demo:limpiar` (`tools/seed.js`), `npm run db:flota` (`tools/seed.js --solo-flota`, production-safe: only seeds the company's own rental fleet, never fake dealers).

**File Storage:**
- Local filesystem only, no S3/cloud object storage.
  - Photos: served/streamed by `tools/fotos.js`, path root from `MERCA_FOTOS` (default outside repo in prod: `/var/lib/mercamaquinarias/fotos`).
  - Videos: served/streamed with HTTP Range support (206 partial content, required for iOS Safari) by `tools/videos.js`, path root from `MERCA_VIDEOS`.
  - Invoices (PDF): generated by `tools/pdf.js` (a from-scratch minimal PDF writer, no `pdfkit`) and `tools/facturas.js`; stored under `MERCA_FACTURAS` (`/var/lib/mercamaquinarias/facturas` in prod), organized by year/month.
  - All three directories are deliberately kept outside the git-managed project directory in production so deploys never touch them and each can be backed up independently.

**Caching:**
- None (no Redis/Memcached). HTTP-level caching only: ETag + `Cache-Control` logic hand-written in `tools/serve.js` (`no-cache` for HTML/CSS/JS in prod to guarantee instant rollout of deploys without hash-named assets; `public, max-age=604800`+ for other static assets; `immutable, max-age=31536000` for randomly-named uploaded photos/videos).

## Authentication & Identity

**Auth Provider:**
- None — fully custom, first-party auth implemented in `tools/db.js` + `tools/api.js`. No Auth0/Clerk/Firebase Auth/Supabase Auth.
  - Passwords: `crypto.scryptSync` with a per-user random salt (`tools/db.js` ~line 893-906), constant-time comparison via `crypto.timingSafeEqual`.
  - Sessions: random 32-byte token (`crypto.randomBytes(32)`) stored server-side and set as an httpOnly cookie (`te_sesion`, via `cookieSesion()` in `tools/api.js`); validated against the database on every request rather than trusting a signed cookie's payload.
  - "Remember this device" cookie: `te_equipo`, separate token, longer-lived (60 days) via `db.recordarDispositivo`.
  - Email verification / login codes: 6-digit numeric codes (`crypto.randomInt`), HMAC-signed with `MERCA_SECRETO` (`crypto.createHmac('sha256', SECRETO)`) so they can be verified without a DB round trip, compared with `timingSafeEqual`.
  - `MERCA_SECRETO`: signs sessions/codes; if it changes, all sessions are invalidated; if leaked, sessions/codes can be forged. Never committed; generated with `node -e "console.log(require('crypto').randomBytes(32).toString('hex'))"`.
  - Rate limiting on sensitive auth ops, defined in `tools/api.js` `LIMITES`: 5 verification codes / 15 min, 10 login attempts / 15 min per IP, 5 new accounts / hour per IP.
  - Roles: `usuarios.es_admin` flag gates `/admin.html`; dealer accounts (`organizaciones`) go through an admin-reviewed approval state (`estado_revision`).
  - No OAuth/social login (no "Sign in with Google" etc.) detected.

## Monitoring & Observability

**Error Tracking:**
- None (no Sentry/Bugsnag/Rollbar). Errors are caught and written to stdout/stderr (`console.error`), captured by systemd/journald in production (`journalctl -u mercamaquinarias -f`). `tools/serve.js` installs `process.on('unhandledRejection', ...)` and `process.on('uncaughtException', ...)` handlers that log and, for uncaught exceptions, exit so systemd restarts cleanly.

**Logs:**
- Plain `console.log`/`console.error` lines (e.g. request status lines like `200  /ruta`), collected by systemd/journald. No structured/JSON logging, no log shipping to a third-party service.

## CI/CD & Deployment

**Hosting:**
- Primary/production: self-managed Ubuntu 24.04 VPS (see `deploy/README.md`), Node process behind Nginx + Let's Encrypt (certbot).
- Historical (decommissioned): Vercel (static-only) once served `proximamente.html` for every route via `vercel.json`, because Vercel cannot run `tools/serve.js` or keep a persistent SQLite file. **That cutover is done.** As of 2026-09-25 the public `mercamaquinarias.com` resolves through Cloudflare to the VPS and serves the real site — verified live: HTTP 200, `Server: cloudflare`, no `x-vercel-*` headers, and `/api/estadisticas` returning real data (a static host cannot do that). `vercel.json` and `proximamente.html` are now leftovers; `deploy/VERCEL.md:66` says to delete them at launch.

**CI Pipeline:**
- GitHub Actions, single workflow `.github/workflows/desplegar.yml` ("Desplegar"). Trigger: push to `main` (i.e., every merged PR) or manual `workflow_dispatch`. Uses `appleboy/ssh-action@v1` to SSH into the VPS as a locked-down `deploy` user and run exactly one whitelisted, sudo-forced command: `/usr/local/bin/desplegar-mercamaquinarias`.
  - That script (`deploy/desplegar-mercamaquinarias`): fixes ownership, `git fetch` + `git merge --ff-only origin/main` (fails loudly rather than merge blindly if the server was hand-edited), restarts the `mercamaquinarias` systemd service, health-checks it for up to 15s, and **automatically rolls back** to the previous commit + restarts if the health check fails.
  - `concurrency: produccion` prevents two deploys racing on the same box.
  - Secrets used: `VPS_HOST`, `VPS_SSH_KEY` (GitHub Actions repo secrets — names only, never values).
  - No automated test suite runs in CI today; `npm run auditar` / `npm run tareas -- --seco` style checks are run manually against a live dev server (see TESTING.md if mapped).

## Environment Configuration

**Required env vars (names only — see STACK.md for the full list):**
`MERCA_SECRETO`, `ANTHROPIC_API_KEY`, `MERCA_CORREO`, `BREVO_API_KEY`, `MERCA_REMITENTE`, `MERCA_SITIO`, `PORT`.

**Secrets location:**
- Development: `.env` at repo root, gitignored, loaded by `tools/entorno.js`.
- Production: `/etc/mercamaquinarias.env`, mode 600, owned by `root`, referenced from `deploy/mercamaquinarias.service` via `EnvironmentFile=`. Non-secret config lives directly in the systemd unit as `Environment=` lines. `tools/entorno.js` reads both the unit file and its `EnvironmentFile` so ad-hoc CLI tools run on the server see identical config to the live service.
- GitHub Actions secrets (deploy-only, not app secrets): `VPS_HOST`, `VPS_SSH_KEY`.

## Other Notable External Touchpoints

- **Google Fonts:** loaded via `<link>`/CSP allowances for `fonts.googleapis.com` / `fonts.gstatic.com` in the CSP set in `tools/serve.js` (`CABECERAS_SEGURIDAD`). The only third-party origins allowed by the site's Content-Security-Policy; everything else (`script-src`, `connect-src`, `media-src` besides `blob:`) is restricted to `'self'`.
- **DGII (Dominican tax authority) compliance:** `tools/facturas.js` implements Dominican fiscal invoicing rules (NCF — Número de Comprobante Fiscal — sequences: B01 credit-fiscal invoices, B02 consumer invoices "not yet approved by DGII", B04 credit notes). This is a regulatory/compliance integration, not an API call — NCF sequences and low-stock warnings (`MERCA_AVISO_NCF`) are tracked locally in SQLite, not fetched from a DGII API.
- **rclone** (external tool, not a code dependency): used per `deploy/README.md` to sync `/var/backups/mercamaquinarias` and the photos directory to off-server remote storage — configuration/credentials for the remote live outside this repo entirely.
